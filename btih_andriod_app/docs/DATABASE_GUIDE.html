2. See ALL tables you can access

All tables owned by the HMIS user:

SELECT table_name
FROM user_tables
ORDER BY table_name;

All tables HMIS can see (other schemas too):

SELECT owner, table_name
FROM all_tables
WHERE owner IN ('HMIS', 'HOSWEB_MVC_LOCAL', 'HOSWEB_MVC_LIVE')
ORDER BY owner, table_name;

In SQL Developer UI (no SQL):

  1. Left panel → Connections
  2. Expand HMISConnection
  3. Expand Tables → full list with row counts

3. See columns of any table

Replace PATIENT_MST with any table name:

SELECT column_name, data_type, data_length, nullable
FROM all_tab_columns
WHERE table_name = 'PATIENT_MST'
  AND owner = 'HMIS'
ORDER BY column_id;

Quick peek at data:

SELECT * FROM PATIENT_MST WHERE ROWNUM <= 10;

4. Main tables for the mobile app

TableWhat it stores
PATIENT_MSTPatient master: name, gender, PATIENT_PASSWORD (login password)
PATIENT_INFORMATIONContact, CNIC, email, blood group, DOB
PATIENT_VISITHospital visits (needed for full profile/history)
MOBILE_SIGNUP_REQUESTMobile app sign-up log (run setup script first)
PRESCRIPTIONSPrescription records
V_LABORATORY_GENLab / gastro / radiology reports (view)

Login uses these two

SELECT pi.MR_NO, pi.CONTACT_NO, pm.FIRST_NAME, pm.PATIENT_PASSWORD
FROM PATIENT_MST pm
JOIN PATIENT_INFORMATION pi ON pi.MR_NO = pm.MR_NO
WHERE pi.CONTACT_NO = '03032431177';

5. View mobile Sign Up records

First time only — run the setup script in SQL Developer:
Open file: HospitalMobileAPPApi/Scripts/create_mobile_signup.sql
Select all → Run Script (F5).

Then query sign-ups:

SELECT id, full_name, contact_no, mr_no, status, created_at
FROM MOBILE_SIGNUP_REQUEST
ORDER BY created_at DESC;

Status meanings

StatusMeaning
REGISTERED_NEWNew patient created in HMIS — can log in
ACTIVATED_EXISTINGPhone already in HMIS — password set — can log in
PENDINGSaved for reception — insert into HMIS failed — cannot log in yet

6. Find tables by keyword

SELECT owner, table_name
FROM all_tables
WHERE UPPER(table_name) LIKE '%PATIENT%'
ORDER BY owner, table_name;
SELECT owner, table_name
FROM all_tables
WHERE UPPER(table_name) LIKE '%BILL%'
   OR UPPER(table_name) LIKE '%APPOINT%'
ORDER BY owner, table_name;

7. Count rows in important tables

SELECT 'PATIENT_MST' AS tbl, COUNT(*) AS cnt FROM PATIENT_MST
UNION ALL
SELECT 'PATIENT_INFORMATION', COUNT(*) FROM PATIENT_INFORMATION
UNION ALL
SELECT 'PATIENT_VISIT', COUNT(*) FROM PATIENT_VISIT
UNION ALL
SELECT 'MOBILE_SIGNUP_REQUEST', COUNT(*) FROM MOBILE_SIGNUP_REQUEST;

If MOBILE_SIGNUP_REQUEST errors, run the setup script first.

10. After implementing Sign Up

  1. Run create_mobile_signup.sql once in SQL Developer
  2. Restart API (start-mobile-dev.bat)
  3. Sign up in the app
  4. Check with the queries below
  5. If canLogin was true in the app, use Login with the same phone + password
SELECT * FROM MOBILE_SIGNUP_REQUEST ORDER BY created_at DESC;

SELECT pi.MR_NO, pi.CONTACT_NO, pm.FIRST_NAME, pm.PATIENT_PASSWORD
FROM PATIENT_MST pm
JOIN PATIENT_INFORMATION pi ON pi.MR_NO = pm.MR_NO
WHERE pi.CONTACT_NO = 'YOUR_PHONE';

11. Safety

  • Live DB — avoid DELETE / UPDATE without IT approval
  • Always use SELECT first
  • Use COMMIT only when you intend to save changes
  • Test patients use MR numbers starting with MOB- from mobile registration
