ButtonWhat it doesUses database?

Sign Up Create or activate mobile login Yes — writes HMIS
Hospital Staff Login Same login UI, different label Same patient API today (staff accounts not built yet)
Login as a Guest Opens dashboard without MR number No — limited features

Where patient credentials are stored

No separate “mobile login” table is required. The hospital HMIS already has everything you need.
TableColumnPurpose
PATIENT_INFORMATIONCONTACT_NOPhone number used as login username
PATIENT_MSTPATIENT_PASSWORDPassword
PATIENT_MSTMR_NOPatient ID (returned after login)
PATIENT_MSTFIRST_NAME, LAST_NAMEName (Sign Up splits full name)

Both tables are linked by MR_NO.

SQL — see who can log in

SELECT pi.MR_NO,
       pi.CONTACT_NO,
       pm.FIRST_NAME,
       pm.LAST_NAME,
       pm.PATIENT_PASSWORD
FROM PATIENT_MST pm
JOIN PATIENT_INFORMATION pi ON pi.MR_NO = pm.MR_NO
WHERE pi.CONTACT_NO IS NOT NULL
  AND pm.PATIENT_PASSWORD IS NOT NULL;

That is the same data the app uses when you log in with test credentials from SQL Developer.

Flow 1 — Patient Login

Welcome → Login → enter phone + password → Flutter calls POST /api/Auth/login → API checks PATIENT_INFORMATION + PATIENT_MST → Returns MR_NO + firstName → App opens Dashboard (isLoggedIn: true)

Code:

  • Flutter: lib/screens/login_screen.dart, lib/services/auth_service.dart
  • API: AuthController.cs → AuthRepository.LoginAsync

Flow 2 — Patient Sign Up

Welcome → Sign Up → name, phone, password → Flutter calls POST /api/Auth/signup → API: If phone already in PATIENT_INFORMATION → UPDATE PATIENT_MST.PATIENT_PASSWORD Else → INSERT new row in PATIENT_MST + PATIENT_INFORMATION (MR number like MOB-250824-1234) → User can log in with same phone + password

Code:

  • Flutter: lib/screens/signup_screen.dart
  • API: AuthRepository.RegisterAsync

Verify sign-up in SQL Developer

SELECT pi.MR_NO, pi.CONTACT_NO, pm.FIRST_NAME, pm.PATIENT_PASSWORD
FROM PATIENT_MST pm
JOIN PATIENT_INFORMATION pi ON pi.MR_NO = pm.MR_NO
WHERE pi.CONTACT_NO = '03001234567';   -- your test phone

Flow 3 — Hospital Staff Login

The welcome screen opens the same login screen with isStaffLogin: true (different title and “Contact Administrator” instead of Sign Up).

There is no separate doctor/admin API yet. Staff would need their own tables and endpoints in a future task.

Flow 4 — Guest

Login as a Guest skips the API and opens the dashboard with:

  • patientMrNo: ''
  • isLoggedIn: false

Guest can browse some screens (e.g. book appointment locally) but cannot see personal records, billing tied to MR number, etc.

Forgot password

Uses existing HMIS data: verify phone → OTP → updatePassword updates PATIENT_MST.PATIENT_PASSWORD.

Quick test checklist

  1. Start API: start-mobile-dev.bat
  2. In SQL Developer, note an existing CONTACT_NO + PATIENT_PASSWORD, or sign up a new phone
  3. Login with that phone + password → should reach dashboard
  4. Sign Up with a new phone → run SQL above → Login again

Common confusion

QuestionAnswer
“Are credentials only in the app?” No. They must be in Oracle (PATIENT_MST + PATIENT_INFORMATION).
“Do I need a new table for Sign Up?” No. Sign Up writes to the same HMIS tables.
“Why could Sign Up fail?” HMIS may require extra columns (NOT NULL, triggers). Fix with IT or register at reception first.
“Is Staff login different?” UI only for now — still uses patient login API.
